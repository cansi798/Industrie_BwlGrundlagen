# Lernapp M-094 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine mobile, offlinefähige Lernapp (GitHub Pages) mit Übungsmodus pro Session und einem Prüfungssimulator (30 Zufallsfragen) aus den 1.620 Quizfragen von M-094.

**Architecture:** Python-Skripte lesen die Quiz-HTMLs einmalig aus und schreiben `data/*.json`. Eine statische Single-Page-App (Vanilla-JS-ES-Module, Hash-Routing) lädt die JSON-Dateien. Die reine Logik (mischen, bewerten, ziehen) liegt isoliert in `js/lib/quiz.js` und ist mit `node --test` getestet. Ein Service Worker macht die App offline nutzbar.

**Tech Stack:** HTML/CSS/JS (ES2022, keine Abhängigkeiten), Python 3.12 (stdlib, unittest), Node 24 (`node --test`), GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-09-lernapp-design.md`

## Global Constraints

- Quelle: `C:/Users/cansi/OneDrive/PC/Desktop/M-094_Teil1_BWL_und_Gesamtdateien/M-094_BWL_Grundlagen`, Dateien `3_Quiz_online_60_Fragen.html`, Ordner mit `BROMIUM` ignorieren, Pfade mit Präfix `\\?\` öffnen.

- Prüfung: 30 Fragen, Bestanden ab 50 % (`>= 15` Punkte), Zeitlimit 45 Min. (standardmäßig an), alles oder nichts pro Frage.
- Antwortflächen mindestens 48 px hoch, ohne horizontales Scrollen ab 360 px Breite, Hell- und Dunkelmodus über `prefers-color-scheme`.
- Jeder Zugriff auf `localStorage` steht in `try/catch`. Schlüssel-Präfix: `m094.`
- UI-Texte auf Deutsch mit korrekten Umlauten.

## Review Focus

- Mehrfachauswahl-Fragen: Wer nur eine von zwei richtigen Antworten ankreuzt, bekommt „falsch“, und die verpasste richtige Antwort wird markiert (Test in Task 2).
- Neuladen mitten in der Prüfung: Die gleichen 30 Fragen kommen in gleicher Antwortreihenfolge mit den bisherigen Antworten zurück, der Timer läuft mit der echten Zeit weiter (Test in Task 2 für `restTime`, manuell in Task 5).
- Auswahl nur eines Tages mit 60 Fragen oder ungleich großer Tage: 30 eindeutige Fragen, nur aus diesen Tagen (Test in Task 2).
- Abgelaufener Timer nach dem Neuladen: sofortige automatische Abgabe statt negativer Zeit (Test in Task 2 für `restTime` ≤ 0).
- Gesperrtes oder volles `localStorage` (privater Modus): Die App läuft weiter, nur ohne Fortschritt (manuell in Task 3).

### Task 2: Quizlogik `js/lib/quiz.js`

**Files:**
- Create: `js/lib/quiz.js`, `tests/quiz.test.mjs`, `package.json` (nur `{"type":"module","private":true,"scripts":{"test":"node --test tests/"}}`)

**Interfaces:**
- Produces (named exports):
  - `shuffle(arr, rand = cryptoRandom) -> Array` (neue Kopie, Fisher-Yates; `rand()` liefert [0,1))
  - `prepareQuestion(q, rand?) -> {id, q, expl, options:[{t,c}], multi:boolean}` (Optionen gemischt, `multi` = mehr als 1 richtig)
  - `isCorrect(question, selectedIdx:Set<number>|number[]) -> boolean` (genau die Menge der richtigen Indizes)
  - `drawExam(poolByDay: Record<string, Question[]>, n = 30, rand?) -> Question[]` (gleichmäßig: `floor(n/k)` pro Tag, Rest auf zufällige Tage mit noch verfügbaren Fragen; Tage mit zu wenig Fragen geben alle ab, der Fehlbetrag geht an andere; Ergebnis gemischt; `n` gekappt auf die Poolgröße)
  - `score(questions, answers: Record<id, number[]>) -> {punkte, gesamt, prozent, bestanden}` (`bestanden = prozent >= 50`, `prozent` gerundet auf eine ganze Zahl)
  - `restTime(endsAt:number|null, now:number) -> number|null` (ms, nie < 0; `null` ohne Zeitlimit)
  - `PRUEFUNG = {fragen: 30, minuten: 45, bestehen: 50}`

- [ ] **Step 1: Write the failing tests** `tests/quiz.test.mjs` mit deterministischem `rand` (z. B. ein LCG mit festem Seed):
  - `shuffle` erhält Länge und Elemente (sortierte Kopien gleich), verändert das Original nicht
  - `prepareQuestion`: gleiche Optionsmenge, `multi` true bei 2 richtigen
  - `isCorrect`: Einfachauswahl richtig/falsch; Mehrfach: beide → true, nur eine → false, beide + falsche → false, leer → false
  - `drawExam`: 3 Tage à 60 → 30 eindeutige IDs, je Tag 10; 1 Tag → 30 aus diesem Tag; Tage 60/5/60 → 30 Fragen, alle 5 vom kleinen Tag enthalten; Pool 20 → 20
  - `score`: 15/30 → bestanden true, prozent 50; 14/30 → false; unbeantwortet zählt falsch
  - `restTime`: `restTime(null, x) === null`; `restTime(1000, 400) === 600`; `restTime(1000, 5000) === 0`
- [ ] **Step 2:** `npm test` → FAIL (Modul fehlt)
- [ ] **Step 3:** `js/lib/quiz.js` implementieren. `cryptoRandom` nutzt `crypto.getRandomValues(new Uint32Array(1))[0] / 2**32`.
